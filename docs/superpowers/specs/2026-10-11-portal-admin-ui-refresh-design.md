## 1. 目标与非目标

### 1.1 目标

1. 后台 7 个视图 + 登录页的**呈现、信息架构、交互**全面重做，达到"专业控制台"的观感与效率。
2. **手机与桌面同等可用**：手机不做降级版，桌面不牺牲密度。
3. 每个视图**首屏先回答一个问题**，再呈现数据（见 §4）。
4. 引入**局部刷新、就地反馈、二次确认**等真实交互，但**保留零构建、零 CDN、零 npm** 的工程姿态。
5. 修掉本次取证确证的既有缺陷（§2.2）。
6. 公开注册页与后台保持同一套设计语言（决策 3）。

### 1.2 非目标（明确不做）

| 不做 | 为什么 |
| --- | --- |
| 浅色主题 | 决策 5 选的是单套中性深色；浅色要状态色/图表/徽标各配一套值，+40% 工作量且容易走形 |
| 批量操作（一次核验多条） | 决策 6：现有规模不需要 |
| 审计导出 CSV | 同上 |
| 服务端推送（SSE / WebSocket） | 4–5 个实例、单机 hub，轮询足够；推送要多一条长连接要维护 |
| CSP（`Content-Security-Policy`） | 有价值但本次不做；**已为其留路**：JS 全部走文件、不内联 `<script>`（§6.2），将来加 `script-src 'self'` 无需改动页面 |
| 公开页引入交互框架 | 公开页面向陌生人，表单保持最轻；只做视觉对齐与必要增强 |
| 改认证 / 核验 / 注册表写入 / 探测判据 | 规格边界（见头部"权威边界"） |

## 2. 现状基线与问题取证

### 2.1 现状结构

- `portal/app.py` **1568 行**，其中：内联样式 `_PORTAL_CSS`（第 87 行起）、页面外壳 `_page()`、组件 `trow()`、HTTP 层 `make_handler()`，以及后台 7 个视图——**全部塞在 `_admin()` 这一个约 300 行的嵌套函数里**（第 1008–1310 行）。
- 呈现方式：纯服务端渲染，**零脚本**；每个动作整页刷新（303 → GET）。
- 已有窄屏能力：720px 断点 + `table.stack` 让宽表堆叠成卡片，靠 `trow()` 写入的 `data-label` 生成小标题。
- 已有守卫：`tests/test_portal.py::test_pages_are_mobile_suitable`（viewport、无内联颜色、`aria-current` 恰一个、每表行格数＝表头列数、CSS 含窄屏规则与 ≥44px 触摸目标）。

### 2.2 已确证的问题（本机可复现，2026-10-11 实测）

| # | 问题 | 证据（复现方式） |
| --- | --- | --- |
| P1 | **登录失败用绿色成功样式** —— 密码输错时页面是绿的 | 本地起服务 `POST /admin/login` 错口令 → `401`，正文含 `<p class=msg>用户名或密码不正确。</p>`，而 `.msg{background:rgba(16,185,129,.08);border:1px solid rgba(16,185,129,.35);color:#34d399;}` —— 唯一的 `.msg` 定义就是绿色 |
| P2 | **英文状态 slug 直接打给运维看** | 「总览」页 `'　'.join(f"{k}={v}" for k, v in sorted(by.items()))` → 实际渲染出 `applied=1　verified=1`；「申请」页状态徽章渲染出 `applied` / `verified` |
| P3 | 申请页七种状态一锅端 | `_admin()` 的 `applications` 视图把 applied/verified/granted/rejected/revoked 全部渲进同一张表，无分组、无计数、无筛选；默认没有任何"只看待处理"的态度 |
| P4 | **拒绝 / 撤销是裸按钮** | `act("/reject", …)` / `act("/revoke", …)` 直接是一个 `<button>`，点击即改 store 与注册表，无二次确认、无理由填入（理由写死在 hidden 字段里） |
| P5 | 实例页一行塞三组事实 | `instances` 视图单行内含：隧道四态、应用状态行+Server 头+构建代号、上游证书主体+签发者+到期+名字比对；窄屏堆叠后一张卡十余行小字 |
| P6 | 隧道历史被浪费 | 采样器已保留每实例 120 样本（≈1 小时），但 `tunnel` 视图只渲染当前值（延时/带宽/流量/连接数），历史仅以"均值/峰值"两个数字出现 |
| P7 | 审计不可查 | `audit` 视图固定 `list(reversed(portal.store.audit()))[:60]`：无筛选、无分页、时间只有 `%m-%d %H:%M`（没有年份、没有相对时间） |
| P8 | 呼号库页几乎无信息 | `clublog` 视图只有一张三行 kv 表；运维核验时最常问的"这个呼号在库里吗"在页面上无法回答 |
| P9 | 导航不承载状态 | 导航是 7 个平级文字链接，没有待办徽标；"有几条申请等我处理"必须逐个点开才知道 |
| P10 | 空状态与错误反馈弱 | 空状态是「（无）」；动作结果只有页面顶部一条 `.msg`，整页刷新后要自己去找 |
| P11 | 弱文字对比度不达标（**本次设计中发现**） | 样张里用作副标题/小字的 `#5b6675` 实测对比度 **3.31:1**（on `#0b0e14`）/ 3.08:1（on `#121721`），低于 WCAG AA 的 4.5:1。已在 §3.4 改定为 `#7c8798` |

### 2.3 取证边界

- 以上问题均**本机复现或代码直读**，不含"用户觉得不好看"这类主观项。
- **未取证**：现网 `portal.mrrc.vlsc.net` 的实际登录/操作手感（本次未登录现网）；hub 主机的真实响应耗时随视图分布。这两项不影响本规格的信息架构决策。
- 本规格**不假设**现网 nginx 配置需要改动（§8 论证）。

## 3. 设计系统

### 3.1 令牌（`portal/ui.py` 内，单处定义）

```
--bg        #0b0e14   页面底
--panel     #121721   侧栏 / 卡片 / 表头
--panel2    #171e29   hover / 次级面
--bd        rgba(255,255,255,.07)
--bd-strong rgba(255,255,255,.13)
--tx        #e6edf3   主文字
--tx2       #93a1b1   次文字
--tx3       #7c8798   弱文字（**不是**样张里的 #5b6675，见 §3.4）
--accent    #22d3ee   焦点环 / 链接 / 图表线（**不承担"重要"语义**）
--ok        #4ade80   正常
--warn      #fbbf24   要注意
--bad       #fb7185   要动手
```

### 3.2 字体与密度

| 项 | 值 |
| --- | --- |
| 字体族 | `Inter, -apple-system, BlinkMacSystemFont, 'PingFang SC', sans-serif`（与 www 一致） |
| 等宽 | `'SF Mono', ui-monospace, Menlo, monospace` + `font-variant-numeric: tabular-nums` |
| 后台正文 | **13px**（现状 15px，太松） |
| 标签 | 9.5px / 大写 / `letter-spacing:.09em` |
| 页标题 | 19px / `letter-spacing:-.022em` |
| 指标数字 | 22px / 等宽 / 粗 |
| 公开页正文 | 15px（保持现状——面向陌生读者，不压密度） |

**数字与标识一律等宽 + 对齐**：端口、延时、流量、剩余天数、证书主体、构建代号。扫列时不需要逐字读。

### 3.3 颜色纪律（本次改版的核心，唯一一条）

> **白 = 强调，色 = 状态。**

- 主按钮 = **白底黑字**（`#e6edf3` / `#0b0e14`）；次按钮 = 透明底 + 边框。
- 青色**不用于**导航选中态、按钮、强调文字；只用于**焦点环、链接、图表线**。
- 绿 / 黄 / 红**只表达状态**，且必须**同时**有文字标签（不靠颜色单独传达信息，兼顾色觉障碍）。
- 反面教材即现状：导航选中、按钮、链接、`<code>` 全是青色 ⇒ 一眼看去全是重点。

### 3.4 对比度实测（2026-10-11 计算，非估算）

| 前景 | on `#0b0e14` | on `#121721` | 判定 |
| --- | --- | --- | --- |
| `--tx` `#e6edf3` | 16.35:1 | 15.19:1 | ✓ AA |
| `--tx2` `#93a1b1` | 7.33:1 | 6.81:1 | ✓ AA |
| ~~`#5b6675`（样张用值）~~ | **3.31:1** | **3.08:1** | ✗ 不达标 |
| `--tx3` `#7c8798`（改定） | 5.31:1 | 4.94:1 | ✓ AA |
| `--accent` `#22d3ee` | 10.69:1 | 9.93:1 | ✓ AA |
| `--ok` `#4ade80` | 11.09:1 | 10.30:1 | ✓ AA |
| `--warn` `#fbbf24` | 11.57:1 | 10.75:1 | ✓ AA |
| `--bad` `#fb7185` | 7.18:1 | 6.67:1 | ✓ AA |
| 主按钮黑字 on 白按钮 | 16.35:1 | — | ✓ AA |

### 3.5 组件词汇（`portal/ui.py` 提供，视图只调用不拼 HTML）

| 组件 | 用途 | 关键约束 |
| --- | --- | --- |
| `page()` | 页面外壳 | 保留 `_page()` 的既有签名与语义；新增片段模式（§6.4） |
| `pill(kind, text)` | 状态徽章 | `kind ∈ {ok,warn,bad,mute}`；**必须带文字**，颜色只是辅助 |
| `stat(label, value, note, kind)` | 指标卡 | 用于总览与详情头部 |
| `toolbar(chips, search, sort)` | 筛选 / 搜索 / 排序条 | 在手机上换行不横滚 |
| `card()` / `kv()` | 卡片与键值对 | 手机上的基本容器（取代 `table.stack`） |
| `banner(kind, text)` | 页内通知 | `kind ∈ {info,ok,warn,bad}`；**取代现有只有绿色一套的 `.msg`**（修 P1） |
| `empty(text, action)` | 空状态 | 必须给"下一步做什么"，取代「（无）」 |
| `sparkline(samples)` | 走势小图 | 内联 SVG，无依赖；**样本缺失即断线，不补 0**（延续诚实降级） |
| `confirm_form()` | 二次确认表单 | 破坏性动作专用，必须带 `csrf` + `data-confirm` + 理由字段（修 P4） |

## 4. 信息架构

### 4.1 全局骨架（决策 4）

**桌面（≥1024px）**：左侧栏 **190px** 固定，分两组——

```
运维   总览 · 实例[异常数] · 隧道 · 系统[告警数]
流程   申请[待办数] · 审计 · 呼号库
侧栏底部：hub 主机 · 已运行天数 · 负载
```

顶栏：面包屑 + 右侧「● 实时 · N 秒前 / 暂停 / 刷新 / 账号」。
**内容区不再限制 960px 最大宽度**（现状宽表被压窄到需要横向滚动）。

**手机（<768px）**：顶栏 = `☰` + 当前视图名 + 实时点；底部固定标签栏 `总览 / 实例 / 隧道 / 申请 / 更多`（「更多」打开抽屉，含系统·审计·呼号库·登出）；有待办的项挂红点。触摸目标 ≥44px。

**窄屏容器的选择**（避免"一个容器打天下"）：
- **实例 / 隧道** 改用**专门卡片**：桌面表格与手机卡片是两份标记，用 `only-desktop` / `only-mobile` 切换。为什么不靠 CSS 把表格捏成卡片——卡片的头部要把标签与状态徽章放在同一行，表格单元格做不到这件事而不引入空的定位格（那又会让"行格数＝表头列数"的守卫失效）；
- **申请 / 系统 / 审计 / 呼号库** 继续用现有的 `table.stack`（单份标记自动堆叠），因此 `data-label` 机制与它的守卫**保留**（§7.1）。

**断点**：720px → **767px**。桌面侧栏在 768px 以上才出现，两者必须对齐，否则 721–767px 这段宽度会出现"有侧栏但没有底部标签栏"的真空。既有守卫里写死了 `@media(max-width:720px)` 这个字符串，随本次一并改（§7.2）。

**徽标语义**：红 = 要动手（异常实例、待核验申请），黄 = 要注意（未安装的服务单元、证书临期）。徽标数字由服务端在渲染导航时计算，**只在 >0 时出现**。

### 4.2 逐视图

以下每条的"首屏回答"是硬要求：视图首屏若没回答它，即视为未完成。

| 视图 | 首屏回答 | 结构 | 相对现状的变化 |
| --- | --- | --- | --- |
| **总览** | 现在有没有事、我该做什么 | ① 四个指标卡（待你处理 / 实例异常 / 入口证书剩余 / 隧道总延时）② **「需要你处理的」清单**：待核验申请、异常实例、未安装的 systemd 单元、证书临期、frps 面板不可用——每条带动作按钮 ③ 隧道 sparkline 列表 ④ 运维命令折叠卡（带一键复制） | 新增待办清单与指标卡；**修 P2**（slug 中文化）；底部 `sudo` 命令从裸文本改为可复制卡片（新增实例后确实仍需人工执行，藏起来会出事） |
| **申请** | 有几条等我处理 | **默认落在「待处理」筛选**；分四组（待核验 / 待分配 / 已授予 / 已结束）各带计数；每条显示核验依据（`Club Log ✓` / "库中未收录，需人工"）、相对时间、联系方式；动作为「核验通过 / 拒绝」 | 修 P3（分组+筛选+计数）；修 P4（拒绝需二次确认 + 填理由）；授予后登记口令与端口**一键复制**（现在要肉眼从表格抄） |
| **实例** | 哪台坏了、坏在哪、我该做什么 | 筛选 chips（全部/异常/服务中/未知）+ 搜索 + 排序；表格每行**两行信息**（主值 + 小字补充），异常行整行描红且第二行直接给**下一步动作**；每行「详情」 | 修 P5：把"隧道/证书/应用"三组事实的细节移入详情页，列表只留一眼判断所需的量 |
| **实例详情**（新增） | 这一台的完整事实 | 头部结论卡（标签、入口 URL、端口、一句话）+ 隧道（四态详情、近 1 小时延时走势含均值/峰值）+ 证书（主体、签发者、到期、名字比对）+ 应用（状态行、Server 头、构建代号）+ **该实例的审计记录** + 动作（撤销入口需二次确认+理由、打开入口） | 新增页面；手机上这是**主入口**（列表卡片太薄） |
| **隧道** | 链路好不好、多少流量、数据新鲜吗 | 每实例一行：状态、延时（**含 sparkline**）、↓↑ 带宽、今日流量、连接数、**采样新鲜度**；底部合计行 | 修 P6（把已有 120 样本画出来）；失败一律如实标注原因，不显示 0 |
| **系统** | 哪一层有问题 | 四分区保留（主机 / 服务 / 隧道层 / 证书），但**每区第一行先给结论**（✅ 正常 / ⚠️ N 项要处理），再是明细；异常服务单元整行标红并可展开看修复命令 | 把"罗列事实"改成"先给判断"；**保留**「本页采集不到的」边界说明（项目诚信纪律，不删） |
| **审计** | 谁在什么时候做了什么、有没有异常登录 | 筛选：按呼号、按事件类型、时间范围；**登录事件单独一组**（`login_ok`/`login_failed`/`login_locked`）；每行补相对时间；**每页 50 条 + 上一页 / 下一页**（服务端 `?view=audit&page=N`，只是读取，仍走 GET） | 修 P7（无筛选/无分页/无年份） |
| **呼号库** | 库是新的吗、这个呼号在不在里面 | 元信息（来源、条数、文件时间、上次同步结果）+ **查一个呼号**：`GET ?view=clublog&q=BG1SB`，命中则显示"在库中"与命中的是哪个库（Club Log / 自建清单），未命中则显示"不在库中 —— 转人工核验"。**纯本地查询，不联网** | 修 P8 |
| **登录页** | — | 品牌 + 表单居中；错误 banner 用红色；锁定倒计时 | **修 P1**（错误提示绿色） |
| **公开注册页** | — | 同一设计语言；**单张表单、三个字段**（呼号 → 联系方式 → 产品）—— **不做分步向导**，不给陌生人增加摩擦；已授予列表改卡片；「为什么必须核验」折叠 | 视觉对齐（决策 3）；正文保持 15px；交互增强仅限表单本身 |

## 5. 交互规范

| 交互 | 规则 |
| --- | --- |
| **自动刷新** | 总览 / 实例 / 隧道默认每 **20 秒**一次；**标签页隐藏即停**、**存在未提交输入即停**、页面可**一键暂停**；顶栏常驻 `● 实时 · N 秒前`。刷新**只替换数据区**，不重排整页、不闪屏、不打断正在选择的文本 |
| **动作反馈** | 就地反馈：目标行变灰 + 结果写回该行；不整页刷新后让运维去顶部找消息 |
| **破坏性操作** | 撤销入口 / 拒绝申请 / 拒绝核验：弹确认框，**必须填理由**；理由写入审计 detail，动作记 `actor` 归因（沿用现有行为，不得丢失） |
| **CSRF** | 所有状态变更表单带每会话随机 `csrf` 字段——**包括本次新增的确认框与详情页动作**，一个不落 |
| **降级（硬要求）** | 所有 htmx 交互都是**渐进增强**：关掉 JS，链接与表单照常工作（退化为整页刷新）。任何"关掉 JS 就点不动"的控件视为缺陷 |
| **空状态** | 「下一步做什么」＋主按钮，禁止「（无）」 |
| **错误** | 红色 banner + 具体原因 + 修复提示；**采集不到的一律如实标注，绝不显示 0** |
| **加载** | 顶部 2px 进度线；探测慢的单元格先出现骨架 |
| **无障碍** | 焦点环可见且用 `--accent`；`aria-current="page"` 标记当前视图；刷新区域 `aria-live="polite"`（**不得**把整页设为 live）；对比度见 §3.4 |
| **不做** | 键盘快捷键（决策 6 排除）、拖拽、右键菜单、动画特效 |

## 6. 技术方案

### 6.1 依赖与 vendor 纪律

- **htmx 2.x**（单文件，~14KB gzip）：局部替换、轮询、就地确认，无需在浏览器建状态模型。**不加 Alpine**——弹窗用原生 `<dialog>`、折叠用 `<details>`、视图切换走服务端 `?view=`。
- **`portal/static/admin.js`**（自写，约 100 行）：暂停自动刷新、确认弹窗、复制按钮、手机抽屉。
- **vendor 纪律（与 `website/css/octen.css` 同一套）**：
  - `portal/static/htmx.min.js` **逐字节冻结**，不得手改；
  - 附 `portal/static/htmx.LICENSE`（BSD-2-Clause）；
  - `portal/static/manifest.json` 记 `{name, version, source_url, sha256}`；
  - **测试校验 sha256**——手改或版本漂移立刻变红。

### 6.2 静态路由

- `GET /admin/static/<name>`，**白名单硬编码**（`htmx.min.js`、`admin.js`、`htmx.LICENSE`），**不做通用文件服务**。
- `Cache-Control: public, max-age=31536000, immutable`；只接受 GET；`Content-Type` 由白名单给定，不由扩展名推断。
- **JS 一律走文件、不内联 `<script>`** ⇒ 将来加 CSP 时 `script-src 'self'` 直接可用（本次不做 CSP）。
- **CSS 仍内联**（`_PORTAL_CSS`）：页面外壳的首要保证是"样式一定在"；公开页不应因静态路由故障而裸奔。代价是将来 CSP 需要 `style-src 'unsafe-inline'`，已知并接受。
- 路径归一化与挂载前缀沿用 `_admin_root()` 的既有做法（**不得**重蹈 2026-10-05 的 `/admin/admin/login` 事故）。

### 6.3 模块拆分（针对性重构）

`app.py` 1568 行、`_admin()` 单函数承载 7 个视图，再加 8 个视图与组件会失控。按"采集 / 呈现 / 传输"三分：

| 文件 | 职责 | 变化 |
| --- | --- | --- |
| `portal/app.py` | HTTP 路由、认证、CSRF、探测与系统事实采集 | **现有逻辑不动**；视图渲染改为调用 `ui` / `views`；继续导出测试依赖的名字（`_PORTAL_CSS`、`make_handler`、`_probe`、`_cert_facts`、`_net_facts`、`_hub_cert_inventory`、`TUNNEL_*` 等） |
| `portal/ui.py` | 设计令牌、`page()` 外壳、组件函数、登录页、公开页 | 新增 |
| `portal/views.py` | 后台 8 个视图（7 + 实例详情） | 新增 |

> 拆分的判定标准：**`views.py` 里不应出现任何 subprocess / socket / 文件读取**；它只消费 `app.py` 采好的事实。做不到就说明边界错了。

### 6.4 片段渲染

- 视图函数**只返回 body**；整页由 `page()` 套壳。
- 请求带 `HX-Request` 头 → 只回片段（**不含 `<html>` / `<head>`**），并回 `HX-Push-Url` 让地址栏可分享。
- 目标元素与 `hx-target` 由外壳给定；刷新区域带 `aria-live="polite"`。

### 6.5 自动刷新的成本与闸门

- 实例页一轮刷新 = 对每个实例各一次完整 TLS 握手探测（并发，单条 2.5s 超时）。
- 现网 hub 规格：**1 vCPU / 1914 MB**（`deploy/README.md`「现行形态」2026-10-03 实测）。5 个实例 / 20 秒一轮可接受，**但必须有闸门**：标签页隐藏即停、有未提交输入即停、可手动暂停。
- 隧道页**直接读采样器**（本来就 30 秒一轮），不额外探测。
- 总览页的实例健康部分与实例页共用同一探测路径，不重复实现。

## 7. 测试与守卫

### 7.1 保留（现有守卫，价值已证明）

`tests/test_portal.py::test_pages_are_mobile_suitable` 中继续有效的不变量：

- 每页有 viewport meta；
- **无内联 `style="color:`**（状态色必须在 CSS 类里）；
- 每个后台视图**恰好一个** `aria-current="page"`；
- **每张表的每行格数 = 表头列数**（这条曾抓出"行构造器少吐一个 td"）；
- CSS 含窄屏断点、`content:attr(data-label)`、`clip:rect(0 0 0 0)`、`min-height:44px`、`overflow-wrap:anywhere`、`.pill.ok`。

### 7.2 替换

- `table.stack` 那套堆叠规则 → 在**改用卡片的两个视图**（实例 / 隧道）上，替换为卡片体系的不变量：**每张移动端卡片必须含状态徽章，且徽章带文字**；并新增"卡片容器 `data-mobile-cards` 与 `only-desktop` 包裹的桌面表格同时存在"的断言——因为手机上表格被隐藏、卡片又漏渲染时，页面会变成一片空白而**不会让任何现有断言变红**。申请 / 系统 / 审计 / 呼号库保留 `table.stack`，对应的 `data-label` 断言一并保留。
- `@media(max-width:720px)` → `@media(max-width:767px)`（断点对齐，§4.1）。
- `aria-current == 1` → `== 2`：侧栏与底部标签栏是两个独立的 `nav`，各自都要标当前页。**不能放宽成 `>=1`** —— 那样"某个 nav 忘了标"就永远测不出来。
- `TUNNEL_COLOR` 已死类字典的守卫保留（内联颜色字典不得复活）。

### 7.3 新增

| 守卫 | 断言 |
| --- | --- |
| 静态白名单 | `GET /admin/static/../portal/app.py` → 404；`GET /admin/static/anything-else` → 404；只有白名单三件可 200 |
| vendor 完整性 | `portal/static/htmx.min.js` 的 sha256 与 `manifest.json` 一致 |
| 片段响应 | 带 `HX-Request` 的请求**不含** `<html` 与 `<head` |
| CSRF 全覆盖 | 渲染出的每个状态变更 `<form>` 都含 `csrf` 字段（按视图逐个断言，不再只测一个动作） |
| 破坏性确认 | 撤销 / 拒绝类表单必须带确认标记与理由字段 |
| 对比度 | §3.4 表中的每个前景色对 `--bg` 与 `--panel` 的比值 ≥4.5。**实现方式**：令牌在 `portal/ui.py` 里以 Python dict `TOKENS` 单处定义并注入 CSS，测试直接读 `TOKENS` 计算比值 —— 不解析 CSS，防后人调色掉档 |
| 降级 | 关掉 JS 时关键路径仍可用：断言页面含真实的 `action='/admin/...'` 与 `href`（不是纯 `hx-get`） |

## 10. 风险

| 风险 | 应对 |
| --- | --- |
| **重构碰坏认证路径** | `app.py` 的认证/CSRF/探测代码**不动**；拆分只搬呈现。既有 49 组测试是回归网，先跑基线再改 |
| **htmx 依赖漂移** | 逐字节冻结 + sha256 守卫；升级必须显式改 manifest 与哈希（一个 commit 看得见） |
| **自动刷新压垮 1 核 hub** | 只有当前视图刷新、隐藏即停、可暂停；隧道页读缓存不探测；上线后观察 `loadavg` |
| **新配色在真机屏幕上偏冷/偏暗** | 样张已按真值渲染并经用户确认；上线后以真机（尤其户外手机）复核一次，必要时只调 `--tx3` / `--bg` 两个值 |
| **`data-label` 时代的窄屏守卫被弱化** | §7.2 用"每卡必有状态徽章"替换，而非直接删除守卫；新守卫必须先能抓到一次故意注入的缺陷（沿用本仓"变异验证"习惯） |
| **公开页被后台改造牵连** | 公开页正文保持 15px、无交互框架；只在视觉层共用 token |
