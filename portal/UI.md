# Portal 界面层：设计系统、组件与交互

> 这份文档讲的是**界面**：令牌、组件、信息架构、交互与前端资源纪律。
> 认证、核验、注册表写入与运维流程的权威仍是 [`README.md`](README.md) 与 SDD。
> 设计规格见 `docs/superpowers/specs/2026-10-11-portal-admin-ui-refresh-design.md`。

## 分层：采集 / 呈现 / 传输

| 文件 | 职责 | 不许做的事 |
| ---- | ---- | ---- |
| `portal/app.py` | HTTP 路由、认证、CSRF、以及**全部事实采集**（subprocess / socket / 文件） | 不拼视图 HTML |
| `portal/views.py` | 8 个视图（7 + 实例详情）：只消费 `Ctx` 产出 HTML | **不读文件、不起进程、不开 socket**（有 AST 守卫盯着） |
| `portal/ui.py` | 设计令牌、样式表、组件、页面外壳（侧栏 / 手机底栏 / 片段模式） | 不依赖任何外部资源 |

`app.py` 把采好的事实装进 `views.Ctx`（纯数据），视图函数返回
`Rendered(title, chrome, live)`：`chrome` 是不需要刷新的部分，`live` 是自动刷新的数据区。

**为什么这样分**：视图层因此可以拿假数据直接测——不起服务、不开端口、不等超时。
`tests/test_portal.py` 里那一组 `vs.render("instances", vs.Ctx(...))` 的用例就是这么来的。

## 设计令牌：`ui.TOKENS` 是唯一来源

```python
TOKENS = {"bg": "#0b0e14", "panel": "#121721", "panel2": "#171e29",
          "bd": "rgba(255,255,255,.07)", "bds": "rgba(255,255,255,.13)",
          "tx": "#e6edf3", "tx2": "#93a1b1", "tx3": "#7c8798",
          "accent": "#22d3ee", "ok": "#4ade80", "warn": "#fbbf24", "bad": "#fb7185"}
```

`ui.CSS` 由它生成，**测试直接读它算对比度**（`tests/test_portal_ui.py::test_tokens_meet_wcag_aa`）。
改任何一个值都要重新过那一关：每个文字色对 `--bg` 与 `--panel` 都必须 ≥ 4.5:1。

> 为什么要有这条守卫：改版时的样张用了 `#5b6675` 当弱文字，实测只有 **3.31:1**，不达 AA；
> 而最接近的修复候选 `#757f90` 在卡片底色上只有 4.44:1。最终定在 `#7c8798`（5.31 / 4.94）。

**唯一一条颜色纪律：白 = 强调，色 = 状态。** 青色（`--accent`）只用于焦点环、链接与
图表线，不承担任何"重要"语义——否则红色出现时就不再是信号。文字色只许用
`.ok-tx / .warn-tx / .bad-tx` 三个类，**不许写内联 `style="color:…"`**（有守卫）。

## 信息架构

**桌面**：左侧栏 190px，分「运维」（总览 / 实例 / 隧道 / 系统）与「流程」（申请 / 审计 /
呼号库）两组，每项可挂待办徽标（红＝要动手，黄＝要注意，只在 >0 时出现）。
**手机**：侧栏收进抽屉，底部固定 `总览 / 实例 / 隧道 / 申请 / 更多`。

每个视图首屏先回答一个问题：

| 视图 | 首屏回答 |
| ---- | ---- |
| 总览 | 现在有没有事、我该做什么（「需要你处理的」清单＋四张指标卡） |
| 申请 | 有几条等我处理（默认落在「待处理」，分三组带计数） |
| 实例 | 哪台坏了、坏在哪、我该做什么 |
| 实例详情 | 这一台的完整事实（隧道 / 证书 / 应用 / 它自己的审计） |
| 隧道 | 链路好不好、多少流量、数据新鲜吗（含 sparkline） |
| 系统 | 哪一层有问题（每区先给结论再列明细） |
| 审计 | 谁在什么时候做了什么、有没有异常登录 |
| 呼号库 | 库是新的吗、这个呼号在不在里面 |

**窄屏容器的分工**：实例与隧道用**专门卡片**（桌面表格与手机卡片是两份标记，
`only-desktop` / `only-mobile` 切换）——卡片头部要把标签与状态徽章放在同一行，
表格单元格做不到而不引入空的定位格；申请 / 系统 / 审计 / 呼号库继续用
`table.stack` 单份标记自动堆叠，`data-label` 机制与它的守卫都保留。

## 交互

- **自动刷新**：总览 30s / 实例 20s / 隧道 30s / 系统 60s。三条停刷理由写在
  `admin.js` 的 `window.__portalPaused()` 里：**标签页隐藏、用户手动暂停、有未提交的输入**。
  刷新只替换 `data-live` 节点，不重排整页。
- **快照与数据龄（V0.36）**：实例事实（隧道四态 + 证书 + 构建代号 + 入口判据）由后台探测器
  每 20 s 探一轮（`metrics.ProbeCache`），**页面渲染只读快照、绝不探测**——实例列表与详情页
  都把这轮的**数据龄**写在头上（「探测每 20 秒一轮 · 数据 3 秒前」，首轮未回则写「探测进行中」）。
  这不只是性能：自动刷新换成读快照后，刷新请求本身变成了毫秒级，切后台/暂停/输入中的
  停刷规则照旧生效。副作用是表头计数与逐行结论现在来自**同一轮**，不会再自相矛盾。
- **破坏性动作**（撤销 / 拒绝）走**服务端两阶段确认**：页面上的表单只发阶段一
  （不带 `confirm`），服务端回确认页，那一步带 `confirm=yes` + **必填理由**才执行。
  JS 在时 `admin.js` 把它弹成 `<dialog>`，关掉 JS 时它是一张普通页面——
  **两条路走同一段服务端代码**，所以降级不会绕开确认。机器路径（`X-Portal-Token`）不受影响。
- **一键复制**：值本身始终渲染在页面上（关掉 JS 也能看见、手抄），按钮默认 `hidden`
  由 `admin.js` 显示——避免留下按了没反应的死按钮。
- **降级是硬要求**：所有 htmx 交互都是渐进增强，关掉 JS 后导航、筛选、表单、
  确认全部照常工作。有守卫逐视图扫（没有内联 `<script>`、每个 POST 表单都有 `action`、
  导航与筛选都是真 `<a href>`）。

## 前端资源与 vendor 纪律

- **htmx 2.0.7** vendored 在 `portal/static/htmx.min.js`，**逐字节冻结**。
  升级必须同时改 `portal/static/manifest.json` 的 `version` 与 `sha256`，并在同一个
  commit 里说明理由；`tests/test_portal_ui.py::test_vendored_assets_match_manifest` 核对哈希。
  当前值：`60231ae6ba9db3825eb15a261122d5f55921c4d53b66bf637dc18b4ee27c79f9`
  （2026-10-11 从 unpkg 与 jsdelivr **两个独立 CDN** 分别下载并比对，字节完全一致）。
- **静态资源只有白名单里的三个名字能被送出**（`htmx.min.js` / `admin.js` / `htmx.LICENSE`）。
  路径是**精确字典查找，不做拼接** ⇒ `/admin/static/../portal/app.py` 一律 404。
  带 `Cache-Control: public, max-age=31536000, immutable`，无需登录（公开库与本站脚本）。
- **JS 一律走文件、不内联**：将来上 CSP 时 `script-src 'self'` 可直接启用。
  **CSS 仍内联**在 `portal/ui.py` 的 `CSS` 里——页面外壳的首要保证是"样式一定在"，
  公开注册页不应因静态资源故障而裸奔。代价是将来 CSP 需要 `style-src 'unsafe-inline'`，已知并接受。

## 上线时要注意的两件事

1. `portal/static/` 必须随源码一起同步到 hub，且 `mrrcportal` 账号**可读**。
2. 会话只存内存，`systemctl restart mrrc-portal` 会让所有人重新登录（已知且接受）。
   **nginx 不需要改**：`/admin/*` 与 `/admin/static/*` 走同一个 proxy_pass
   （仍建议按 `deploy/README.md` 的检查单在 hub 上实测确认一次）。
