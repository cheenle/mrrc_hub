# 2. Business Direction

## 2.1 价值主张

| 用户痛点（现状） | Hub 提供 |
|---|---|
| 想让朋友收听/操作，需要公网 IP、端口映射或 IPv6，还要在中心机改 nginx（B2：每实例每资源一条 `location`） | **扫码绑定即通**：客户侧零入站、零配置，中心零人工（AD-H01、AD-H02、UC-H01） |
| 多用户无法分权：现状是共享一个实例密码（admin 或 listen） | **用户 → 实例 → 角色**：Owner / Operator / Listener / Fleet Admin，服务端强制（AD-H05、AD-H08） |
| 两个人同时控制同一部电台会产生不可预期的发射 | **单写多读**：每实例最多一个 Operator 租约，冲突排队或降级（AD-H05） |
| 远程操作的安全边界不明：令牌进 URL、TLS 校验被关（B2） | **统一安全基线**：一机一证、一次性 code、令牌不进 URL/日志（AD-H07、AD-H11） |
| 出问题时作者只能让用户手动导出日志 | **可运营**：在线状态/版本/隧道/租约/PTT 事件可观测，OTA 灰度可控（AD-H13、UC-H09） |

## 2.2 市场定位与替代方案

| 方案 | 客户侧成本 | 多用户/角色 | 与 MRRC 的耦合 | 定位 |
|---|---|---|---|---|
| **B2 现状：IPv6 直连 + 中心 nginx** | 需要 IPv6；无 IPv6 则不可用 | 无（共享密码） | 手工、逐实例 | 本产品的**前身**，保留为退化路径（AD-H10） |
| Tailscale / Headscale | 客户装客户端 + 账号体系 | 组网层可隔离，但 Web 用户入口仍需代理 | 弱 | 高级用户自带网络 |
| Cloudflare Tunnel | 客户装客户端 | 无应用级角色 | 第三方数据路径 | 小规模验证备选 |
| frp 等成熟反向隧道 | 客户多一个进程 | 无 | 需自建编排 | **MVP 验证手段**（AD-H04） |
| **MRRC Cloud Hub（本产品）** | **零配置**（安装即绑定） | **完整角色与租约** | **载实例上下文、可统一 OTA** | 正式产品目标（AD-H01、AD-H11、AD-H13） |

**差异化不在"能穿透 NAT"**（多种方案都能），而在**能承载业务语义**：
角色/租约/PTT 安全/审计/OTA 与电台上下文 —— 这正是通用隧道方案不提供的部分。

## 2.3 商业模式与成本结构

| 项 | 说明 |
|---|---|
| 成本驱动 | 公网出带宽（活跃会话数 × 0.2–0.48 Mbps）、连接数/fd、RDS/Redis、OSS/CDN 流量 |
| 成本杠杆 | 频谱占单会话 ~86%（AD-H14）—— 降瀑布帧率是唯一显著杠杆 |
| 可能的收费边界 | 免费：LAN + B2 直连 + 基础远程接入；付费：多用户角色、Operator 租约、云端录音备份（I-H4）、配额与 SLA |
| 明确不做 | 不强制云端录音；不经 Hub 分发 OTA 包（走 OSS/CDN，NFR-H018） |

## 2.4 隐私与信任立场（产品级承诺）

Hub 模式意味着**远程访问数据会经过作者侧服务器**（源文档 §10.2）。因此：

- 隐私政策与 ToS 必须写明数据路径、用途、保存范围与责任边界。
- 默认**不保存音频**；QSO 云备份必须单独开启，并提供保留期限、导出与删除。
- **永久保留** LAN 直连与用户自建隧道/直连能力（AD-H10、SC-H8），使"不希望音频经过 Hub"的用户有出路。
- 客户端（GPLv3 项目）随包发布的 Fleet Agent 继续遵守 GPLv3；Cloud Hub 作为独立网络服务单独设计许可，上线前做正式合规审查（R-H11）。

## 2.5 业余无线电合规

远程操作电台需符合用户所在地执照、遥控台站与发射规范。平台在**首次启用 Operator 能力时提示用户确认**；
技术上保留地区策略与紧急禁用入口，但不替代用户的合规责任（NFR-H024、源文档 §10.4）。
