## 背景与问题

站点内容基线停在 2026-10-01/06，而 10 月 hub 侧又走了三步（门户公开/后台全面改版、
远程协助通道、换机可见性）。线上 `https://www.vlsc.net/mrrc_hub/` 同时落后于**已提交**的
本地校正：2026-10-16 的 `f4e4fba` 把 V0.21 事实校正（只剩 443、`:9988`/`:8899` 取消、
海外边缘入口删除）与中文标点/引号规整提交进仓，**但未发布**——线上仍在教人用两个已取消的端口。

四类缺口：

1. **过期事实**：线上入口表、证书说明、"Layer 0–7" 等仍是迁港前口径（本地已改，发布即可生效）。
2. **未写入的新能力**：门户自助注册闭环、**远程协助**（v1.26.0 起，应用内「开启协助/停止协助」）、
   **换机**（同呼号新密钥）在 portal 实例页的可见判据（2026-10-16）。
3. **缺失的入口形态**：W103D 盒子（镜像内置 frpc + `cloud_hub.py`）已是合法且省事的实例形态，
   站上只字未提；新做的**电台站接线拓扑图**（`mrrc_modern/website/images/station-topology.svg`，
   commit `defacb6`）没有归处。
4. **缺失的生命周期操作**：换机/迁移、撤销与退出（撤销≠吊销、退出应用留孤儿）、
   证书重签后必须重启进程——这些是 10-11/10-16 两次现场事故的直接结论，目前只在 SDD 里。

## 2. 每页结构

### index.html（首页）

1. **Hero**：主张不变（零入站、一个呼号一个入口），三按钮（开始接入 / 看设计与实现 / 源码）
   + 统计带。统计数字**以现场复核为准**（见 §4）；测不到可比口径就换不带数字的表述并标注测量日期。
2. **系统地图**：`station-topology.svg`（替换现有 div 版「30 秒看懂信号走到哪」）。
   图讲两件事：射频链在本地；盒子分出**局域网直连**与**frp 隧道**两条进入方式。
3. **四条主张**：保留（客户侧零入站 / 一个呼号一个入口 / PTT 释放永远在本地 / 逐跳校验证书），
   按 v1.26.0 后的实现现状复核措辞。
4. **两条入口卡**：`我要接入`（→ `start.html`）与 `我在用`（→ `use` / `maintain` / `trouble`）。
5. **能力现状表**：保留 live/todo/gap 徽标制；10 月新增行（远程协助 / 换机判据 / 盒子接入）。
6. **你该从哪开始**：改为按意图指引（自己接入 / 帮别人接入 / 只是看看）。

### start.html（接入）

1. 前提自检（保留，核对现网要求）。
2. **选路径**：盒子（W103D）与电脑（macOS / Windows / Linux）并列。盒子段复用拓扑图局部说明，
   细节链到 `https://www.vlsc.net/mrrc_modern/zh/w103d.html`（完整指南，现网 200）。
3. 注册：门户自助（`portal.mrrc.vlsc.net`，核验通过才授予；呼号即入口名）。
4. 装隧道 / 开箱：安装器行为、Windows 无幂等闸门、盒子直接接线。
5. 验通：三条命令，含「HEAD 得 405，要用 GET」这条实测坑。
6. 重启之后：常驻语义（打包版 vs 源码运行）、**证书重签后必须重启进程**。

### use.html（使用与分享）

入口怎么选（公网 / 局域网）→ 两把口令两个角色 → 监听者可调频是刻意的 → 分享给朋友 →
手机上用 → 已知退化（更新 10 月口径）。

### maintain.html（维护与生命周期，新建）

1. **换机 / 迁移**：同呼号、新密钥 → 重新登记（`/enroll`）→ hub 侧信任包与 nginx 重载
   （30 s timer 自动）；判据在 portal 实例页（指纹对比 / 登记↔实到 / 待重载）。
2. **证书与续期**：实例自签证书链、由 hub 验签；hub 通配证书自动续期（运维侧，不展开内部细节）。
3. **撤销 / 退出**：撤销≠吊销（portal `revoke` 移除路由，证书信任另行处理）；退出应用要确认
   隧道子进程一并退出（留孤儿会占端口）；重接入的正确顺序。
4. **远程协助**：应用内「远程协助 → 开启协助」；**口令在你手里**、不落盘、不写日志；
   三条关闭路径（你按停止 / 窗口到期 / 维护者被强制结束）；全程可审计。
5. **版本升级 / 热修**：链到产品侧升级指引，不在此重复步骤。
6. **什么时候找维护者**：怎么提交诊断包（🐞）、怎么约远程协助。

### trouble.html（排障）

症状表补：证书重签后入口 502、换机后 404/502 判据、隧道残留（退出应用留孤儿）、
「TCP 没断」的掉线（心跳闸门默认关，Hub 模式下实例侧建议开启）、端口被占。
四跳分诊补：502 vs 404 vs 超时的分辨方法（404 = 未登记/未知实例；502 = 上游不可达/证书不匹配；
超时 = 隧道不在）。保留两条诊断命令与日志位置。

### design.html（设计与实现）

六节骨架保留，更新：V0.21 单机与入口收敛、路由 timer（30 s 自动再生）、实例证书链（一机一证、
信任包、逐实例校验名）、远程协助通道（回环两端、无持久口令、三条关闭路径）、门户三件套
（apply/status/verify/grant/enroll/revoke + 协助端点）、令牌不进 URL 现状（v1.25.4+）。
事实基线日期改为 **2026-10-16 现场复核**。

## 5. 验证与发布

1. 本地闸门 = `website/README.md` §5 ①–④：金规则 grep、断链/标签平衡/锚点脚本、
   `octen.css` 与上游哈希一致、现网入口仍符合页面描述。
2. **用户过目**：发布前把改好的站（本地预览或 diff 摘要）给用户确认。
3. 发布：`bash deploy.sh --yes`（脚本自带备份、nginx 幂等、逐页实测）。
4. 发布后：逐页 `curl` 状态码 + 关键文案线上抽查（例如入口表、远程协助段、拓扑图 URL 200）。
5. 提交：`website/` 变更 + `website/README.md` 事实源映射 + `SDD/14-version-history.md` 一条；
   **不夹带**工作区里其他会话的未提交文件（SDD/.agents/deploy 的现存改动）。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 远程协助的用户可见细节（时限、按钮名）与代码不一致 | 以 `mrrc_modern` 当时已发布版本的代码/UI 为准，不引用设计稿 |
| 首页统计数字测不到可比口径 | 换成不带数字的表述，或标注测量日期与网络路径 |
| 现场复核与 SDD 冲突 | 以现场为准，回改页面与 README，并更新事实基线日期 |
| 发布前用户未过目 | 发布闸门（§5.2）是硬门槛，`deploy.sh` 不在确认前执行 |
| 新增页造成断链/锚点失效 | README §5 ② 脚本作为发布前硬闸门 |
