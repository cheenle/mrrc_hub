# MRRC Cloud Hub 文档站全面改版设计

日期：2026-10-05
状态：已与用户对齐（定位 / 语言 / 透明度三问已答）
发布目标：`https://www.vlsc.net/mrrc_hub/`

## 背景与问题

站点写于 2026-10-01/02，此后 portal 侧迭代到 V0.28（2026-10-05），公开站停在旧口径：

- 申请令牌 → `/status` 轮询 → `/claim` 自助取回凭证的闭环（V0.17/V0.18）未写入接入指南；
- `design.html:441-443`「授予后路由由 root 手执行」已过时（V0.17 起 30s 定时自动再生，10-03 现网装齐）；
- `use.html` gaps 表的脚本漂移描述仍是 10-01 口径（V0.21 后 8899/9988 明文回退已失去对象、trust-bundle 已写回脚本，活漂移仅剩 `proxy_ssl_name` 一处）；
- 首页是"文档站首页"而非"价值落地页"，功能模块与价值不突出。

## 已确认的三条方向（用户拍板）

1. **定位：价值主张前置。** 首页先讲清 Hub 是什么、解决什么、功能模块与价值；文档退为支撑。
2. **语言：全面转向产品文案。** 标题说价值、正文首句说收益、机制细节跟后。诚信底线不破：不虚构能力，待做项如实标注，"实测/待核实"纪律保留。
3. **透明度：运维侧不上公开站。** admin 审批台、隧道性能监控（延时/带宽/流量）、按操作员账号、审计归因——一律不写进公开站，只留在 SDD。

## 方案

采用方案 A：首页重构为落地页，四页文档做支撑。否决方案 B（新增 features.html 独立模块页）：信息分散、多维护一份骨架，且"功能模块与价值"应在首屏一屏内可见。

## 1. 信息架构（五页不变，角色重排）

| 页面 | 新角色 | 本次动作 |
| --- | --- | --- |
| `index.html` | 落地页 | 重写区块顺序与文案（见 §2） |
| `start.html` | 接入指南 | 注册步补 `/claim` 自助取回凭证闭环；语言产品化 |
| `use.html` | 使用与分享 | gaps 表按 V0.21 后口径修订；语言统一 |
| `trouble.html` | 排障 | 结构不动，语言统一 |
| `design.html` | 工程页 | 修"root 手执行路由"过时表述；语言轻刷 |

导航五项不变，所有既有 URL 与锚点保持有效。

## 2. 首页区块（自上而下）

1. **Hero**：主标讲价值（"人在哪里，电台就在哪里"方向），副标一句机制（零入站、一个呼号一个入口）。保留实测数据带（118–168 ms 公网往返、5 个 WS 端点、0 入站端口、Layer 0–7 本地释放），数字全部沿用已有实测，不发明新数字。
2. **痛点对照**：没有 Hub（要公网 IP / 端口映射 / 4G·公司网无计可施）vs 有了 Hub（一条出站连接全解决）。新组件 `hub-versus` 两栏。
3. **功能模块卡（本次核心）**：统一入口（呼号子域）、零入站出站隧道、五路 WS 透明转发、主/监听双口令、全链路证书校验、PTT 本地释放兜底。每张卡一句价值 + 一句机制。3 列网格。
4. **数据路径**：现有"30 秒看懂信号走到哪"五层图保留。
5. **能力现状表**：保留实测诚信表（live/todo badge 不动），待做项压缩呈现。
6. **双路径 CTA**："还没装 MRRC Modern" / "局域网已经能用"，保留。

## 3. 语言体系

- 术语表钉死，全站一致：**电台 / 实例 / 隧道 / Hub / 入口 / 主口令 / 监听口令**。
- 句式：短句、动词开头；标题说价值，正文首句说收益。
- 不虚构：待做项仍用 `hub-badge todo` 如实标注；无法取证的写"待核实"。

  - `hub-versus` — 痛点前后对照两栏；

3. `<body data-site="mrrc_hub">` 不变。
